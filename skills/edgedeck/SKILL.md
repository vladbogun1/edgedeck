# EdgeDeck

Панель маршрутизации сервера: домены → контейнеры, статика, редиректы. Стоит поверх
Caddy (`edge_caddy`) на каждом сервере, у каждого сервера своя копия. Репозиторий:
`vladbogun1/edgedeck` (приватный), локально `D:\CLOUDE\apps\edgedeck`. Устройство и
причины решений — `DESIGN.md` в репозитории.

## Главные правила

- **Источник истины — `~/edge/routes.yaml`.** Файлы `~/edge/sites/*.caddy` генерируются из
  него; руками их не править — перезапишутся. Руками живёт только `_default.caddy`
  (обработчик по умолчанию → панель).
- Применять только через панель или CLI: `docker exec edgedeck edgedeck --plan`, затем
  `--apply`. Это снимок, проверка конфига самим Caddy до записи, контроль всех доменов и
  автооткат. `~/edge/bin/reload` перегенерацию **не** делает.
- Пояснения к маршруту — в поле `comment:`. Обычные YAML-комментарии теряются при сохранении.
- Перед правкой `routes.yaml` сделать бэкап:
  `tar czf ~/edgedeck/backup/routes-$(date +%F-%H%M).tgz -C ~/edge routes.yaml sites`.
- Цель должна быть в docker-сети, которую видит Caddy. Стандарт — сеть `edge`
  (`networks: {edge: {external: true}}` в compose проекта). Панель сама возвращает сеть
  после пересоздания контейнера, но в compose прописать правильнее.
- Все серверы — **arm64**. Образы только `linux/arm64`.
- Секреты (`~/edgedeck/.env`: токены бота, агента, пароль) в чат и в файлы не выводить.

## Подключить новый сайт (самый частый сценарий)

1. Понять сервер: прод → s1, новое/демо → s3; на s2 сайтов нет, там :443 занят VPN (xray).
2. A-запись домена → IP сервера. Проверка: `nslookup домен 1.1.1.1`.
3. Контейнер цели запущен и в сети `edge`; порт — внутренний порт контейнера, а не
   опубликованный на хост.
4. Добавить маршрут в `~/edge/routes.yaml` (поля — `references/routes-yaml.md`).
5. `docker exec edgedeck edgedeck --plan` → посмотреть список изменений, затем
   `docker exec edgedeck edgedeck --apply --reason "что сделали"`.
6. Сертификат Caddy выпустит сам за ~1 мин. Проверка:
   `curl -sI https://домен/`, без лишних заголовков `Server`/`X-Powered-By`/`Via`.

Если домен из **новой зоны** (не поддомен уже настроенного сайта) и маршрута ещё нет,
панель ему не отвечает (421) и сертификат не выпускает — это защита от чужих доменов,
направленных на наш IP. Создание маршрута снимает вопрос; либо кнопка «это мой домен» в
панели.

## Как проверять, что ничего не сломалось

- `--apply` сам сравнивает ответы всех доменов до и после и откатывает при регрессии;
  вывод — таблица «было/стало».
- Для крупных переносов (например, файл руками → маршрут) сравнить итоговый конфиг Caddy:
  `docker exec edge_caddy caddy adapt --config <Caddyfile> --adapter caddyfile` для
  старого и нового набора `sites/` во временной папке, затем сравнить маршруты по хостам.
- Снаружи: `curl -sI https://домен/путь` (из Git Bash ставить `MSYS_NO_PATHCONV=1`, иначе
  `/путь` превращается в путь Windows).

`skills/sync.ps1` — он поставит свежую версию из GitHub в `~/.claude/skills/edgedeck`.
